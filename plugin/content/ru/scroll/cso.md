## Что это

Обход трёх мест, где чаще всего утекают ключи и пароли от чужих сервисов.
API-ключ — пароль, по которому сервис узнаёт вашу программу. Кто знает
ключ, тот тратит ваши деньги и лимиты.

Обход занимает несколько минут и ничего в проекте не меняет. Ассистент
только смотрит и составляет список найденного.

Ключ компьютера для GitHub — другое. Он лежит вне проекта, в папке `.ssh`,
и его открытую часть показывать можно.

## Когда применять

- Перед первой отправкой проекта на GitHub.
- После того как подключили новый сервис и получили ключ.
- Если ключ мог засветиться: в переписке с людьми, на снимке экрана, в
  чужом чате.
- Раз в месяц просто так: ключи копятся быстрее, чем кажется.

## Как делать

Скажите ассистенту: «Проверь, не утекают ли ключи». Он посмотрит три места.

1. **Файл `.env` в сохранениях.** Ключи лежат в файле `.env`. В сохранения
   и на GitHub он не попадает: его закрывает строка `.env` в файле
   `.gitignore`. Файл нашёлся в сохранениях — ключи из него считайте
   утёкшими.
2. **Ключи в истории.** Файл удалили вчера, а в старом сохранении он
   остался навсегда. Поэтому смотрят всю историю сохранений, а не только
   последнюю версию.
3. **Ключи в коде.** Ключ, вписанный прямо в файл кода. Его ищут по словам
   `token`, `key`, `secret`, `password` и по виду: у многих ключей
   узнаваемое начало, например `sk-` или `ghp_`.

Итог — список найденного: самое опасное первым. Найденный ключ ассистент
не повторяет, а называет файл и строку. Чисто — так и пишется: «ключи не
утекают».

Проверить сами без ассистента можно двумя командами. Первая обязана не
найти ничего, вторая — назвать файл:

```
git ls-files | grep -E '(^|/)\.env$'
git check-ignore .env
```

**Если ключ утёк**, порядок ровно такой. Сначала выпустите новый ключ в
кабинете сервиса, а старый отзовите. Новый положите в `.env`, из кода
старый уберите. Переписывать историю сохранений не нужно: отозванный ключ
больше не работает. Наоборот бессмысленно: пока старый ключ жив, он
работает у всех, кто его видел.

## Чего не делать

- Не убирайте ключ из кода раньше, чем отозвали его: он уже утёк.
- Ключ можно отдать ассистенту, чтобы он положил его в `.env`. Посторонним
  его не показывайте, в код и в открытое хранилище не кладите.
- Не держите ключи в открытом хранилище на GitHub. Открытое видят все.
- Не считайте закрытое хранилище сейфом. Ключ всё равно живёт в `.env`, а
  не в сохранениях.
