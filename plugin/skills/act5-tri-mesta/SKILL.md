# Акт 5 · Три места кода

Язык — по `content/ru/language.md` плагина: фразы до 15 слов, без образов.

Читатель прошёл четыре вечера: его сайт или бот работает на его компьютере,
у проекта есть сохранения. Копии нигде нет: сломается компьютер — пропадёт
всё. Мысль этого вечера одна: код живёт в трёх местах — на компьютере, на
GitHub и на сервере, и везде одна версия. Акт — пятый вечер и пять квестов:
GitHub, приватный репозиторий, одна версия, чужой сервис, третье место.
Сегодня два места из трёх; о третьем, сервере, — только рассказ. Выкладку
на сервер падаван делает вместе с автором игры, на личной консультации:
как записаться, скажет финал.

**Наружу — только его хранилище, и только закрытое.** Ничего не создавай на
GitHub без слова падавана. Открытых хранилищ не делай вовсе. Артефакты и
страницы в интернете не публикуй. Набор SDD в этот вечер не применяй.

**Ничего не ставь без вопроса.** Подключить GitHub можно без установки:
`git` и `ssh` на его компьютере уже есть. Программу `gh` ставь, только если
падаван сам попросил и согласился на скачивание. `sudo` не зови.

**Ключ не повторяй.** API-ключ — пароль, по которому сервис узнаёт
программу. Он живёт только в файле `.env`. В ответах ключ не повторяй, в
код не вписывай.

**Ключей сегодня два, и они разные.** Ключ компьютера (`~/.ssh`) пускает
компьютер на GitHub: его открытую часть показывать можно, файл без `.pub` —
никому. API-ключ сервиса не показывают посторонним. До квеста «Чужой
сервис» говори только «ключ компьютера»: про ключи сервисов там и речь.
Спросил, можно ли показывать ключ, — ответь про открытую часть и файл без
`.pub`, не забегая вперёд.

**Экран игры читает и падаван.** Игра печатает ему слова: названия квестов
и задания. Команд и кодов квестов на экране нет — они здесь, в этом файле.
Падавану их не диктуй и не показывай: команды игры запускаешь ты.

**Сайт GitHub английский.** Каждую строку, которую он там увидит, назови
заранее с переводом. Одно сообщение — один шаг.

**Есть инструмент игры — зови его.** Инструменты игры стоят в твоём списке
инструментов: их имена начинаются с `mcp__jedicoder__`. Инструмент делает
то же, что команда, без строки в терминале. Номер акта и код квеста ему не
нужны. Инструментам `check`, `seen` и `ack` назови квест словами из столбца
«На экране»: `quest: "GitHub"`. Назвал не тот квест, что открыт, — игра
ничего не запустит и скажет, какой открыт.

Инструмента нет в списке — выполни команду в терминале. Инструмент ответил
по-английски, что команда не выполнилась, — тоже. Квест не закрылся или
акт не начат — это ответ игры, а не сбой: в терминале команду не повторяй.
Падавану про инструменты не говори: есть они или нет, он не выбирает.

## Перед началом

1. Следуй контракту. В системном промпте есть раздел
   `# Jedicoder — поведенческий контракт` — контракт уже у тебя: команду не
   запускай. Раздела нет — загрузи контракт командой:
   `python3 "$(cat ~/.jedicoder/plugin_root)/lib/jedicoder/cli.py" contract`
   Есть инструмент игры `contract` — зови его вместо этой команды.

2. Акт уже идёт — первый экран назвал открытый квест. Тогда не входи заново:
   иди к разделу этого квеста. В папке проекта лежит `HANDOFF.md` — сначала
   прочитай его и скажи падавану одной фразой, на чём вы остановились.

3. Акт не начат — войди: инструмент `enter`. Инструмента нет — командой:
   `python3 "$(cat ~/.jedicoder/plugin_root)/lib/jedicoder/cli.py" enter 5`

4. Игра напечатала две фразы о том, что будет в акте, и за ними список
   квестов с заданиями. Две фразы прочитай падавану дословно. Единственный
   источник: `content/ru/acts/act5-tri-mesta.md`. Своей катсцены у скилла
   нет и быть не должно. Список квестов по строкам не пересказывай.

   Список на экране свёрнут: Claude Code прячет длинный ответ игры. Поэтому
   следом назови пять квестов одной строкой:

   > Сегодня пять квестов: «GitHub», «Приватный репозиторий», «Одна
   > версия», «Чужой сервис» и «Третье место».

5. Скажи одной фразой про приём с экрана:

   > Приём этого акта — «Проверка ключей». Перед отправкой кода скажи:
   > «проверь, не утекают ли ключи».

   Команду приёма падавану не называй: он её не набирает. Попросил —
   примени приём `/jedicoder:cso` сам.

6. Игра напечатала вопрос про Книгу — задай его тем же сообщением и на
   этом остановись. Вопрос в сообщении один.

   > У игры есть Книга: те же акты страницами в браузере. Открывать её в
   > начале каждого акта? Ответь «да» или «нет».

   Ответ запиши **этой командой**: сама игра терминал не читает.

   ```bash
   python3 "$(cat ~/.jedicoder/plugin_root)/lib/jedicoder/cli.py" book yes
   # или ... book no
   ```

   Игра напечатала строку про ключ от бота игры — про ключ сам не
   заговаривай. Падаван назвал такой ключ — запиши его командой `link`:

   ```bash
   python3 "$(cat ~/.jedicoder/plugin_root)/lib/jedicoder/cli.py" link <ключ>
   ```

   Вопроса про Книгу на экране нет — не задавай: в приложении Голокрон
   Книга открыта справа.

7. Начинай квест 01.

## Квесты

Игра зовёт квест по названию. Код и команду бери из этой таблицы.
Последний столбец — инструмент игры, который зовёшь вместо команды. Квест
ему называешь словами из второго столбца, без кавычек-ёлочек.

| Код | На экране | Что делает падаван | Как закрывается | Инструмент игры |
|---|---|---|---|---|
| `01-github` | «GitHub» | заводит аккаунт, добавляет ключ компьютера на сайте, подтверждает имя аккаунта | `ack 5 01-github` | `ack` |
| `02-private` | «Приватный репозиторий» | создаёт на сайте закрытое хранилище, присылает адрес, говорит «отправляй» | `check 5 02-private` | `check` |
| `03-sync` | «Одна версия» | просит поправить мелочь, проверяет, говорит «сделай коммит и отправь на GitHub» | `check 5 03-sync` | `check` |
| `04-service` | «Чужой сервис» | даёт ссылку на документацию сервиса и ключ, рассказывает, что продукт теперь умеет | `seen 5 04-service`, потом `check 5 04-service` | `seen`, потом `check` |
| `05-server` | «Третье место» | слушает про сервер и домен, пересказывает своими словами | `ack 5 05-server` | `ack` |

Порядок жёсткий.

## Как вести каждый квест

1. **Возражение Магистра** — правило 7 контракта — в этом акте звучит в
   квесте «Чужой сервис»: падаван сам называет, зачем продукту сервис.
   Спроси, что продукт будет уметь с ним.
2. Каждое слово, которое падаван слышит впервые, объясни примером в той же
   фразе. Новых слов на квест — не больше трёх.
3. Одно сообщение — один шаг. Обязательные слова квеста говори по частям и
   жди ответа.
4. Квест закрыт — скажи об этом и остановись. Следующий квест начни
   следующим сообщением, когда падаван ответит.
5. Прогони проверку: инструмент `check`. Инструмента нет — командой:
   `python3 "$(cat ~/.jedicoder/plugin_root)/lib/jedicoder/cli.py" check 5 <код квеста>`
6. Не сошлось — объясни **только** непройденные пункты и помоги исправить.
7. «Не смог проверить» — не провал: прочитай причину и устрани её.
8. Третья неудача на одном квесте — игра скажет остановиться и позвать
   Магистра. Так и сделай: в четвёртый раз тем же способом не пробуй, зови
   `/jedicoder:magistr`.

**Не видит — сделай сам.** Всё, что можно сделать в терминале, делай сам.
Сам за него ты не можешь одного — сайта GitHub: аккаунт, ключ компьютера и
хранилище там заводит он. Там объясняй по одному шагу. Не нашёл кнопку —
пусть вставит снимок экрана, как во втором вечере: ты назовёшь строку.

**Сломалось само — без паники.** Сломалось — примени приём
`/jedicoder:investigate`: «Разбор поломки». Ошибку целиком — текстом или
снимком экрана.

## Квест 01 — GitHub

Новые слова: Git и GitHub. Объясни одним сообщением:

> **Git** — программа на твоём компьютере. Она хранит сохранения, ты
> знаешь её с первого вечера.
>
> **GitHub** — сайт, где лежит копия твоих сохранений. Сломается
> компьютер — скачаешь проект с GitHub, ничего не пропадёт.
>
> Аккаунт на GitHub есть? Если нет — зарегистрируйся на github.com.
> Ставить ничего не надо, только регистрация.

Нет аккаунта — назови шаги регистрации с переводом: `Sign up` —
«зарегистрироваться»; почта, пароль и имя латиницей; код из письма GitHub.
Имя аккаунта будет в адресе проекта — пусть выберет простое.

Дождись ответа. Аккаунт есть — скажи: «Теперь скажи мне: „у меня есть
GitHub, как его подключить?“». Эту фразу он скажет и без игры.

**1. Посмотри, что есть.** Одной командой, ничего не меняя: адрес
`origin`, есть ли `gh`, есть ли ключ в `~/.ssh`, имя и почта в git.

**2. Ключ компьютера.** Путь без установки — ключ `ssh`. Объясни:

> Нужен **ключ компьютера** (пропуск, по которому GitHub узнаёт именно твой
> компьютер). Я сделаю его сам, интернет для этого не нужен.

Ключ уже лежит в `~/.ssh` (`id_ed25519.pub` или другой `.pub`) — возьми
его, новый не делай и старый не перезаписывай. Нет — сделай:
`ssh-keygen -t ed25519 -C "<имя папки проекта>" -f ~/.ssh/id_ed25519 -N ""`.
Покажи открытую часть — содержимое файла `.pub` — одной строкой. Скажи,
что открытую часть показывать можно, а файл без `.pub` — никому.

**3. Ключ компьютера на сайт.** По одному шагу, с переводом:

1. На github.com нажми на свою картинку справа вверху → `Settings` —
   «настройки».
2. Слева — `SSH and GPG keys` — «ключи». Кнопка `New SSH key` — «новый
   ключ».
3. `Title` — «название»: что угодно, например «Мой ноутбук». В поле `Key`
   вставь строку целиком.
4. `Add SSH key` — «добавить». Сайт может спросить пароль или код — это
   GitHub проверяет, что это ты.

**4. Проверь и назови аккаунт.** Он написал, что добавил, — проверь:
`ssh -T -o StrictHostKeyChecking=accept-new git@github.com`. GitHub
отвечает `Hi <имя>! You've successfully authenticated…` — «привет, ты
вошёл». Код возврата у этой команды 1 — это нормально. Назови имя
аккаунта и спроси: «Это твой аккаунт?»

`Permission denied (publickey)` — ключа на сайте нет. Частые причины: ключ
лёг в `GPG keys` вместо `SSH keys`, строка вставлена не целиком, сайт
просил подтверждение, а окно закрыли.

**5. Почта.** Почта в сохранениях — та, по которой GitHub узнаёт его
правки. Спроси, какую почту указать: почту аккаунта или скрытый адрес
GitHub (`Settings` → `Emails`, вида `…@users.noreply.github.com`). Запиши
её в git только по его ответу.

**Путь `gh`** — только если падаван сам попросил войти через браузер.
Скажи, что программу надо скачать из интернета, и спроси разрешения.
Разрешил — скачай официальный выпуск с GitHub без `sudo`, в
`~/.local/bin`, и сверь контрольную сумму. Вход ждёт его ответа, поэтому
команду наберёт он сам, с `!` в начале:
`! gh auth login --hostname github.com --git-protocol https --web`.
Скажи заранее: появится `First copy your one-time code` — «вот код»;
открой `https://github.com/login/device`, введи код и нажми
`Authorize GitHub CLI`.

**6. Подтверди:** он сказал, что аккаунт его, — инструмент `ack`.
Инструмента нет — командой:
`python3 "$(cat ~/.jedicoder/plugin_root)/lib/jedicoder/cli.py" ack 5 01-github`

Не подтверждай, пока GitHub не назвал имя, а падаван не сказал «да».

## Квест 02 — приватный репозиторий

Новые слова: репозиторий и приватный. Объясни одним сообщением:

> **Репозиторий** (хранилище) — та же папка проекта, только на GitHub.
>
> Открытый репозиторий видят все — так выкладывают программы для всех.
> **Приватный** (закрытый) видишь только ты.
>
> Твой проект — для тебя, поэтому репозиторий приватный.

**1. Хранилище на сайте.** Создаёт его он — так «закрытое» выбирает он
сам. По одному шагу, с переводом:

1. На github.com — `+` справа вверху → `New repository` — «новое
   хранилище».
2. `Repository name` — «имя»: латиницей, как папка проекта.
3. Выбери `Private` — «закрытое». Это главное.
4. Галочки `Add a README file`, `.gitignore`, `license` не ставь: всё
   нужное уже есть в проекте.
5. `Create repository` — «создать». Откроется страница хранилища. В
   рамке `Quick setup` нажми `SSH` и скопируй адрес вида
   `git@github.com:<имя>/<папка>.git`. Пришли его мне.

Прислал адрес `https://github.com/<владелец>/<имя>` — он там стоит
первым. Без `gh` отправка по нему спросит пароль и упадёт. Не проси
пароль: возьми из адреса владельца и имя и свяжи проект по адресу ssh —
`git@github.com:<владелец>/<имя>.git`. Падавану скажи одной фразой: ты
взял адрес для ключа компьютера, который сделали в прошлом квесте.

Вошёл через `gh` — можешь создать сам, по его слову:
`gh repo create <имя> --private --source=. --remote=origin`. Только
`--private`.

**2. Перед отправкой — проверка ключей.** Примени приём «Проверка
ключей» (`/jedicoder:cso`): `.env` не в сохранениях, ключей нет в истории
и в коде. Нашёл ключ — сначала скажи падавану, отправку отложи.

**3. Отправка.** Скажи, что уйдёт на GitHub: файлы проекта и все
сохранения; `.env` не уйдёт. Его слово «отправляй» — и:
`git remote add origin <адрес>`, затем `git push -u origin <ветка>`.

**4. Проверка:** инструмент `check`. Инструмента нет — командой:
`python3 "$(cat ~/.jedicoder/plugin_root)/lib/jedicoder/cli.py" check 5 02-private`

Проверка смотрит три вещи по шагам: проект связан с хранилищем на GitHub,
код отправлен, хранилище закрытое. Закрытость она спрашивает у GitHub без
входа: закрытое чужим не видно.

- «Хранилище открытое» — скажи: `Settings` → внизу `Danger Zone` →
  `Change visibility` → `Make private`. GitHub попросит ввести имя
  хранилища — это защита от случайного нажатия.
- «Не смог проверить» — нет интернета или GitHub попросил подождать.
  Проверь интернет и VPN, повтори позже.

Квест закрыт — скажи: «Теперь копия проекта лежит на GitHub. Сломается
компьютер — подключишь GitHub на новом и скачаешь проект». Остановись.

## Квест 03 — одна версия

Мысль квеста: порядок всегда один. Поправил на компьютере → сохранение →
отправка на GitHub. Руками он этого не делает — говорит словами. Скажи
одним сообщением:

> Код живёт в трёх местах: на компьютере, на GitHub и на сервере. Везде
> должна быть одна версия.
>
> Порядок всегда один: поправил → сохранил → отправил на GitHub. Руками
> ничего не делаешь: говоришь словами, делаю я.
>
> Попроси меня поправить мелочь в продукте: надпись, цвет, кнопку.

**1. Правка.** Он назвал мелочь — сделай её и скажи, как посмотреть. Сам не
сохраняй и не отправляй: ждёшь его слов.

**2. Сохранение и отправка.** Он посмотрел и сказал: «Сделай коммит и
отправь на GitHub». Сохрани правку (`git add` её файлов, `git commit`),
потом `git push`. `.env` в сохранение не клади.

**3. Проверка:** инструмент `check`. Инструмента нет — командой:
`python3 "$(cat ~/.jedicoder/plugin_root)/lib/jedicoder/cli.py" check 5 03-sync`

Проверка смотрит три вещи по шагам: после входа в акт есть новое
сохранение, несохранённых правок нет, на GitHub та же версия. В сеть она
не ходит: сравнивает с тем, что git запомнил о GitHub при отправке.

- «Несохранённых правок нет» не сошлось — в папке есть файлы без
  сохранения. Покажи их списком (`git status`) и спроси, сохранить ли.
  Памятка игры в `docs/jedicoder` — тоже его файлы, их сохраняют.
- «На GitHub та же версия» не сошлось — подсказка называет, что разошлось.
  Не отправлено — отправь. На GitHub новее — по его слову скачай
  (`git pull`). Разошлись — объясни одной фразой и по его слову сведи
  (`git pull`). Спор правок покажи и спроси, какую оставить.

Квест закрыт — скажи: «Теперь на компьютере и на GitHub одна версия. Так —
после каждой готовой правки». Остановись.

## Квест 04 — чужой сервис

Новые слова: API, API-ключ и MCP. Первое объясни одним сообщением:

> **API** — способ, которым программа просит сервис о деле. Например:
> «какая погода в Уфе?»
>
> Подключить сервис — научить продукт так просить. Разбираюсь в этом я, от
> тебя — ссылка на документацию.

**1. Зачем.** Возражение Магистра: спроси, что продукт будет уметь с
сервисом. Ответ — одна фраза о пользе его продукту.
