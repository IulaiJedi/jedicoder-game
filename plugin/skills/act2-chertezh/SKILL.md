# Акт 2 · Чертёж

> *«План прежде кода. Иначе Сила пишет то, что ей вздумается»*

## Перед началом

1. Загрузи контракт и следуй ему: `python3 "$(cat ~/.jedicoder/plugin_root)/lib/jedicoder/cli.py" contract`
2. Войди в акт: `python3 "$(cat ~/.jedicoder/plugin_root)/lib/jedicoder/cli.py" enter 2`
3. CLI напечатал текст катсцены — прочитай его падавану дословно, не
   пересказывая. Единственный источник: `content/ru/acts/act2-chertezh.md`.
   Своей катсцены у скилла нет и быть не должно.
4. Скажи, что он получил артефакт `plan`.
5. Если игра напечатала вопрос про Голокрон — задай его падавану своими
   словами и запиши ответ **этой командой** (сама игра терминал не читает):

   ```bash
   python3 "$(cat ~/.jedicoder/plugin_root)/lib/jedicoder/cli.py" book yes
   # или ... book no
   ```

## Квесты по порядку

| Квест | Что делает падаван |
|---|---|
| `01-recipe` | выбирает стек по рецепту своего типа продукта, пишет `ARCHITECTURE.md` |
| `02-claude-md` | пишет `CLAUDE.md` — что делает проект, из чего состоит, как запустить |
| `03-db-schema` | описывает таблицы в `DB-SCHEMA.md` |
| `04-git-init` | `git init` и первый коммит |
| `05-env-guard` | `.env` и правило в `.gitignore` |
| `06-pipeline` | разбирает схему пайплайна разработки |

Порядок жёсткий. Не предлагай перескочить: `03` требует ответа из `01`,
а `05` — репозитория из `04`.

## Как вести каждый квест

1. **Возражение Магистра** — правило 7 контракта, загруженного шагом 1.
2. Помоги сделать. Термин впервые — поясни одной фразой в скобках.
3. Прогони проверку:
   `python3 "$(cat ~/.jedicoder/plugin_root)/lib/jedicoder/cli.py" check 2 <квест>`
4. Не сошлось — объясни **только** непройденные пункты и помоги исправить.
5. Третья попытка — CLI напечатает протокол выхода из круга. Выполни его.

## Квест 01 — важная деталь

Спроси падавана, есть ли в его проекте база данных, и запиши ответ **этой
командой** (руками `state.json` не правь — состояние пишется только через CLI):

```bash
python3 "$(cat ~/.jedicoder/plugin_root)/lib/jedicoder/cli.py" project db yes
# или ... project db no
```

Без записанного ответа квест `03` не проверяется — вернёт «не смог проверить».
Ответ хранится в состоянии как `project.has_db`.

Заодно убедись, что игра знает папку проекта — в ней гоняются все проверки:

```bash
python3 "$(cat ~/.jedicoder/plugin_root)/lib/jedicoder/cli.py" project path /путь/к/проекту
```

Папка — одного продукта, а не общая свалка: `git init` этого акта заведёт
историю на всё, что в ней лежит, и разделить её потом уже нельзя.

## Квест 05 — здесь играется врезка

Это врезка уровня квеста, а не катсцена акта: она про ключ, уехавший в
открытый репозиторий, то есть ровно про то, что проверяет этот квест.
Живёт она здесь и больше нигде.

Перед проверкой расскажи историю: автор игры однажды работал на сервере
под root, и через уязвимость ему поставили майнер Monero — сервер пришлось
сносить. Начинается такое почти всегда одинаково: ключ, уехавший в
открытый репозиторий.

Если проверка `no_secrets_in_history` провалилась — это не косметика.
Сначала падаван меняет сам ключ, только потом чистит историю.

## Квест 06 — обучающий, без автопроверки

Покажи схему и объясни, что это цикл, а не прямая:

```
локалка → гит → выкладка → правки на локалке → отправил → подтянул → ⟲
```

Убедись, что падаван может сказать своими словами, где он сейчас на этой
схеме. Потом закрой квест:
`python3 "$(cat ~/.jedicoder/plugin_root)/lib/jedicoder/cli.py" ack 2 06-pipeline`

## Финал акта

Все квесты закрыты — поздравь и объяви ранг **Падаван**. Скажи, что дальше
Акт 3 «Первая кровь», где проект впервые оживёт и впервые сломается, и
что это нормально.
