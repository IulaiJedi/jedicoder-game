# Приём: Проверка безопасности

Язык — по `content/ru/language.md` плагина: фразы до 15 слов, без образов.

## Замок

Тот же принцип, что и с квестами: исход решает exit-код, а не мнение
модели. Прежде чем браться за дело — выполни:

```bash
python3 "$(cat ~/.jedicoder/plugin_root)/lib/jedicoder/cli.py" artifact cso
```

Решение принимает только код возврата этой команды — не текст, который она
напечатала, и не то, насколько готовым выглядит падаван.

- **Код `1`** — приём ещё не выдан. Ответь коротко и **останови
  выполнение здесь**, не переходя к разделу «Что делаешь»:

  > Этот приём выдаётся на входе в Акт 4. Дойди до Щита — и он твой.

  Не пересказывай вывод команды дословно.
- **Код `0`** — приём открыт. Работай дальше.

## Что делаешь

Проходишь по четырём местам, где утекают ключи. Ничего не меняешь — только
читаешь и докладываешь.

1. **Секреты в индексе.** `git ls-files | grep -E '(^|/)\.env$'` — файл
   `.env` не должен быть под контролем git; `.gitignore` обязан его
   закрывать (`git check-ignore .env`).
2. **Секреты в истории.** `git log -p --all` — ищи строки, похожие на
   ключи: `sk-…`, `ghp_…`, `github_pat_…`, телеграмные `NNNNNNNN:AA…`.
   Нашёл — порядок один: сначала отозвать и перевыпустить сам ключ,
   потом чистить историю.
3. **Секреты в коде.** Токены и пароли, вписанные строками в исходники,
   даже вне git.
4. **Доступ.** Спроси падавана: включена ли 2FA на GitHub и хостинге,
   когда он в последний раз менял токены, не работает ли он на сервере
   под root.

## Доклад

Список дыр по убыванию опасности, по каждой — что чинить первым и почему.
Начинай с самой опасной, не с самой лёгкой. Если чисто — так и скажи:
«Нарушений нет», без придуманных замечаний для солидности.
