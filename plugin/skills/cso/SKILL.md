# Приём: Проверка ключей

Язык — по `content/ru/language.md` плагина: фразы до 15 слов, без образов.

## Замок

Тот же принцип, что и с квестами: исход решает exit-код, а не мнение
модели. Прежде чем браться за дело — выполни:

```bash
python3 "$(cat ~/.jedicoder/plugin_root)/lib/jedicoder/cli.py" artifact cso
```

Решение принимает только код возврата этой команды — не текст, который она
напечатала, и не то, насколько готовым выглядит падаван.

- **Код `1`** — приём ещё не выдан. Ответь коротко и **останови
  выполнение здесь**, не переходя к разделу «Что делаешь»:

  > Приём «Проверка ключей» выдаётся на входе в Акт 5. Начни акт — и он
  > твой.

  Не пересказывай вывод команды дословно.
- **Код `0`** — приём открыт. Работай дальше.

## Что делаешь

Смотришь три места в папке проекта, где утекают ключи. Ключ — пароль, по
которому чужой сервис узнаёт программу: ключ бота, ключ от сервиса погоды.
Ничего не меняешь — только читаешь и докладываешь.

Читатель — новичок. Его проект — сайт или Telegram-бот на его компьютере и
копия на GitHub. Говори его словами: «сохранение», «файл `.env`», «ключ».

Ключ компьютера для GitHub (`~/.ssh`) — не про этот приём: он лежит вне
папки проекта, и его открытая часть не секрет. Не ищи его и не пугай им.

1. **Файл `.env` в сохранениях.** `.env` — файл, где лежат ключи. Его не
   сохраняют в git и не отправляют на GitHub.
   `git ls-files | grep -E '(^|/)\.env$'` обязана не найти ничего, а
   `git check-ignore .env` — назвать файл.
2. **Ключи в истории.** Файл удалили вчера, а в старом сохранении он
   остался. Смотри всю историю: `git log -p --all`. Ищи строки, похожие на
   ключи: `sk-…`, `ghp_…`, `github_pat_…`, `AIza…`, ключ бота — цифры,
   двоеточие и длинный хвост.
3. **Ключи в коде.** Ключ, вписанный прямо в файл кода, даже если файл
   ещё не сохранён. Ищи по словам `token`, `key`, `secret`, `password` и
   смотри, что стоит справа от знака `=`.

Найденный ключ в ответе **не повторяй**: назови файл и строку, сам ключ —
нет. Хранилище на GitHub открытое — скажи это первым: тогда любой ключ в
нём уже видели все.

## Доклад

Список найденного: самое опасное — первым. По каждой строке — что сделать
и почему именно это. Одна фраза — одна мысль.

Ключ утёк — порядок один. Сначала выпусти новый ключ в кабинете
сервиса, а старый отзови. Новый — в `.env`, из кода старый убери.
Историю сохранений не переписывай: отозванный ключ уже не работает.
Пока старый ключ жив, он работает у каждого, кто его видел. Ключ бота
меняет `/revoke` у @BotFather.

Чисто — так и скажи, коротко и по трём местам. Без придуманных замечаний
для солидности:

> Ключи не утекают.
>
> Файл `.env` закрыт от сохранений. В истории сохранений и в коде ключей
> нет.

Ничего не исправляй сам без слова падавана. Попросил — исправь по одному
пункту и сохрани.
