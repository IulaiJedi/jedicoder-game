# Акт 0 — Пробуждение Силы

Установка Claude Code: от «есть только оплаченная подписка» до работающей
команды в терминале.

Тот же текст лежит ещё в двух местах — в Telegram-боте и страницей на сайте.
Это одна инструкция за тремя дверями, и ни одна из них не обязательна:
поставить можно по любой.

Шаги идут в том порядке, в каком их проходят. Ссылки в конце шага —
развилки: они ведут туда, где продолжается именно твой случай, а не туда,
куда идут все.

## По шагам

<a id="node-start"></a>

### Перед началом

Дальше — установка Claude Code. Это то, чем ты будешь работать весь путь: ты
пишешь словами, что нужно сделать, оно пишет код и правит файлы у тебя на
машине.

Ставится всё одной строкой, и строка эта одна на все системы. А вот
подготовка разная: где-то её нет вовсе, а где-то нужен один шаг до. Поэтому
сначала скажи, где ты работаешь.

<a id="node-windows"></a>

### Windows — сначала WSL

Claude Code на Windows работает. Anthropic поддерживает и обычный Windows, и
WSL — если где-то написано обратное, это неправда.

А вот проверки этой игры написаны для bash, языка команд Linux. Обычный
Windows их не выполнит. Поэтому мы поставим WSL — настоящий Linux внутри
твоего Windows.

Нажми правой кнопкой по кнопке Пуск и выбери в меню Windows PowerShell
(администратор). Набери там:

```
wsl --install
```

Перезагрузи компьютер. После перезагрузки откроется окно Ubuntu и попросит
придумать имя и пароль — это отдельный пользователь внутри Linux. Всё
дальнейшее ты делаешь в этом окне.

Одна грабля заранее: позже, на входе в аккаунт, браузер из WSL может не
открыться сам, а вместо него появится код. Это штатное поведение.

### Оплаченный план

Один вопрос до установки — чтобы ты не упёрся в него шагом позже и не решил,
что сломалось.

Claude Code в бесплатный аккаунт не входит. Он открывается только оплаченным
планом. Поставить его можно и без оплаты, всё пройдёт гладко — а развернут
тебя уже на входе в аккаунт, и по ответу там будет непонятно, при чём тут
деньги.

Какие сейчас планы и почём — смотри на сайте Anthropic. Сюда мы это не
переписываем: цены меняются, а текст остаётся, и получилась бы ложь.

<a id="node-no-plan"></a>

### Пока двигаться нечем

Тогда скажу честно: дальше двигаться нечем. Claude Code — это то, чем игра
играется, и без оплаченного плана он не откроется. Ни обойти, ни отложить на
потом внутри игры это нельзя.

Что делать: оформить план на сайте Anthropic и вернуться. Путь никуда не
денется и начнётся ровно с того же места — команда /start приведёт тебя
сюда снова.

Ставить Claude Code прямо сейчас, до оплаты, смысла нет. Он поставится, а на
входе в аккаунт тебя всё равно развернут — и ты потратишь вечер на то, чтобы
понять, почему.

<a id="node-install-linux"></a>

### Установка на macOS Linux и WSL

Открой терминал — окно, где с компьютером говорят текстом, а не мышкой. На
Linux он чаще всего открывается сочетанием Ctrl+Alt+T; на macOS и в WSL окно
у тебя уже открыто.

Выполни в нём одну строку:

```
curl -fsSL https://claude.ai/install.sh | bash
```

Это официальный установщик. Он положит всё, что нужно, к тебе в домашнюю
папку и дальше будет обновляться сам.

Прав администратора он не просит. Если у тебя спрашивают пароль — ты
выполняешь не эту строку, вернись и перечитай.

Когда строка отработает и снова появится приглашение ввода, возвращайся сюда.

```
curl -fsSL https://claude.ai/install.sh | bash
```

<a id="node-permissions"></a>

### Первый вечер — кого ты пускаешь за руль

Сейчас ты начнёшь жать «да» на каждое действие. Так у всех на второй день:
Claude Code по умолчанию спрашивает разрешения на всё, что меняет твою
машину.

Правильный следующий шаг — не «снять проверки», а сузить круг того, о чём
тебя спрашивают. Ступени такие:

— пока не умеешь посмотреть, что изменилось, и вернуть как было — оставайся
в осторожном режиме, где спрашивают про каждое действие;
— научишься — включишь режим, где правки файлов идут молча;
— ступенью выше решает отдельная проверяющая модель: это не гарантия, а
фильтр, и он стоит денег и времени.

Режим без проверок вообще существует для изолированных виртуалок. На
машине, где ты живёшь, его не включают: он не защищает ни от чего.

Что включено прямо сейчас — написано в строке статуса внизу окна.
Переключается сочетанием Shift+Tab.

<a id="node-model-choice"></a>

### Первый вечер — чем именно за тебя думают

Моделей несколько, и они разной силы. У каждой есть ещё мощность
рассуждения — насколько глубоко она думает перед ответом. Чем выше, тем
дороже и медленнее.

Приём, который бережёт тебя с первого вечера: пока вы только придумываете,
что строить, держи самую мощную. Появился готовый план — отдавай его той,
что попроще. Разговор «что мы вообще строим» стоит того, чтобы за него
думали хорошо. Исполнение по готовому плану — уже нет.

Делают чаще наоборот: обсуждают будущее с самой быстрой моделью, а к среде
обнаруживают, что работать уже нечем.

Какая модель включена сейчас, покажет команда /status. Сменить её — /model,
он же откроет список. Мощность рассуждения переключает /effort.

Имён моделей я не называю намеренно: набор меняется чаще, чем этот текст.
Открой /model и посмотри, что предлагают тебе сегодня.

### Ещё одна проверка перед игрой

Игра считает твой прогресс сама, и делает это на python3. Он стоит почти
везде, но не везде — проверим одной строкой:

```
python3 --version
```

Годится любой ответ, начинающийся с «Python 3». Номер после тройки не важен.

Зачем это сейчас, а не по ходу дела. Без python3 игра поставится, но не
запустится, и выглядеть это будет обманчиво: как будто надо перезапустить
Claude Code. Перезапускать можно долго. Полминуты здесь дешевле испорченного
вечера потом.

```
python3 --version
```

### Поставь игру

Теперь сама игра. Две строки — в том же терминале, не внутри Claude Code:

```
claude plugin marketplace add IulaiJedi/jedicoder-game
claude plugin install jedicoder@jedicoder
```

Первая говорит Claude Code, где игру брать. Вторая её ставит.

Теперь запусти Claude Code в папке проекта, над которым будешь работать, и
набери:

```
/jedicoder:start
```

Именно первой командой в свежей сессии — это важнее, чем кажется. Правила
игры подхватываются при старте сессии, и разговор, начатый раньше, пойдёт
мимо них: игра будет вести себя странно, а ты не поймёшь почему.

<a id="node-link-key"></a>

### Ключ привязки

Осталась одна строка. Ключ привязки — короткая строка, по которой твой путь в
игре и этот чат узнают друг друга: пройденные квесты, ранг и находки будут
видны и здесь, а не только у тебя на машине.

Сразу, чтобы не было недопонимания: ключ — не пропуск. Он ничего не открывает
и ничего не проверяет. Игра проходится целиком и с непривязанным паспортом —
просто тогда весь путь останется на твоей машине.

Держи ключ и команду к нему. Плагин у тебя уже стоит, так что выполнить её
можно прямо сейчас — одной строкой в терминале.

### Ищем каталог установки — bash

Так отвечает bash — оболочка по умолчанию в Linux и в WSL. Проверим главное
подозрение: система не знает, где лежит поставленное.

Выполни:

```
echo $PATH | tr ':' '\n' | grep -Fx "$HOME/.local/bin"
```

Эта строка ищет каталог установки в списке мест, где система ищет программы.
Ответ бывает ровно двух видов: либо она напечатает путь, либо не напечатает
ничего.

Пустой ответ здесь — не ошибка, а находка: значит каталог в список не попал,
и мы знаем, что чинить.

```
echo $PATH | tr ':' '\n' | grep -Fx "$HOME/.local/bin"
```

<a id="node-fix-bash"></a>

### Починка списка путей — bash

Каталог в списке не значится. Допишем его туда — один раз и навсегда:

```
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

Первая строка дописывает каталог в файл настроек bash, чтобы он подхватывался
при каждом запуске. Вторая перечитывает этот файл прямо сейчас.

Вместо второй строки можно просто закрыть окно и открыть заново — официальная
документация называет оба способа одинаково рабочими. Если у тебя открыто
несколько окон, закрывать надо то, в котором ты работаешь.

Теперь вернись к проверке версии: она и покажет, помогло или нет.

```
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
```

<a id="node-which-claude"></a>

### Сколько установок и откуда

Каталог в списке есть, а команда всё равно не находится. Значит смотреть надо
не туда: вопрос не «где искать», а «что нашлось и откуда оно взялось».

```
which -a claude
```

Команда печатает все найденные копии по порядку — первая в списке и есть та,
которая запускается.

Три исхода, и все три нам о разном:

— пусто: установщик не дошёл до конца, его надо выполнить заново;
— путь заканчивается на .local/bin/claude: это наш, поставленный официальным
установщиком;
— путь ведёт куда-то ещё: у тебя чужая установка, и разбирать её надо
отдельно.

```
which -a claude
```

<a id="node-foreign-install"></a>

### Чужая установка

Значит Claude Code стоит у тебя не тем способом, которым мы его ставим. Так
бывает: в интернете до сих пор советуют ставить его пакетным менеджером
узла, а он ставит то же самое в другое место.

Откуда именно — покажут три строки:

```
ls -la ~/.local/bin/claude
ls -la ~/.claude/local/
npm -g ls @anthropic-ai/claude-code
```

«No such file or directory» в первых двух — не ошибка, а ответ «здесь пусто».

Самый частый случай: npm с нестандартным местом установки. Оно не добавляет
свой каталог в список путей — это делает человек руками. Отсюда и «команды
нет» при полностью успешной установке.

```
npm -g ls @anthropic-ai/claude-code
```

<a id="node-win-shell"></a>

### Это окно самого Windows

Так отвечают оболочки самого Windows — значит команду ты набираешь не в том
окне. Различить их можно по началу строки ввода: в PowerShell она начинается
с букв PS и дальше диск, в командной строке — сразу с диска.

Проверки этой игры написаны для bash, и ни одна из этих двух оболочек их не
выполнит. Нам нужно окно WSL.

Посмотри в PowerShell, что WSL на месте:

```
wsl --list --verbose
```

Есть дистрибутив в списке — набери wsl и нажми Enter: ты внутри Linux, и все
команды теперь набираешь там.

Список пуст или команда не найдена — WSL ещё не стоит.

```
wsl --list --verbose
```

<a id="node-fix-path-win"></a>

### Починка списка путей — Windows

Это починка для самого Windows — на случай если Claude Code ты ставил в него,
а не в WSL. Команда после неё заработает, но проверки игры из Windows всё
равно не пойдут: им нужен bash.

Посмотри в PowerShell, есть ли каталог в списке:

```
$env:PATH -split ';' | Select-String '.local'
```

Пусто — добавь его через настройки системы: Параметры → Система → О системе →
Дополнительные параметры системы → Переменные среды. В верхнем списке найди
строку PATH, нажми «Изменить» и добавь %USERPROFILE%\.local\bin отдельной
строкой.

Закрой окно и открой заново — иначе новый список не подхватится.

Для командной строки Windows шаги ровно те же: список путей у них общий.

```
$env:PATH -split ';' | Select-String '.local'
```

<a id="node-wsl-mix"></a>

### WSL подхватил чужое

Внутри WSL легко подхватить программы из самого Windows: он видит их пути. И
тогда всё выглядит установленным, а работать отказывается.

```
which node
which npm
```

Путь начинается с /mnt/c — это программа из Windows. Начинается с /usr или с
твоей домашней папки — это своя, линуксовая. Нужна своя.

Три поломки из этого семейства и их починки:

— «exec: node: not found» при запуске: среда взята из Windows. Поставь её
внутри WSL пакетным менеджером своего дистрибутива.
— npm жалуется на несовпадение платформы: выполни npm config set os linux и
повтори установку. Прав администратора для этого не нужно.
— менеджер версий стоит и в Windows и в WSL: допиши его загрузчик в ~/.bashrc
последней строкой, чтобы WSL брал свой.

```
which node
```

<a id="node-wsl-version"></a>

### Первая версия WSL вместо второй

Ещё одна частая причина — старая версия самой WSL. Признак у неё
однозначный: «cannot execute binary file: Exec format error».

Посмотри в PowerShell:

```
wsl --list --verbose
```

В колонке VERSION должна стоять двойка. Стоит единица — переключи, подставив
своё имя дистрибутива из той же таблицы:

```
wsl --set-version Ubuntu 2
```

И отдельно, раз ты здесь: если браузер из WSL не открывается сам, а вместо
перехода печатается код — это не поломка. Скопируй код из браузера на Windows
и вставь обратно в окно WSL.

```
wsl --list --verbose
```
